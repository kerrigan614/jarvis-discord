What the bot does

Core features

J.A.R.V.I.S. supports the day-to-day operation of two MARVEL Strike Force Discord communities. Availability and behavior depend on each server's configuration and channel permissions.

Commands and interactions

Use an actual bot mention followed by the command in server channels, such as @J.A.R.V.I.S. help or @J.A.R.V.I.S. weekly. Type @ and select J.A.R.V.I.S. from Discord's suggestions. Counting uses /count; giveaway entries and role selections use their configured buttons, reactions, and dropdowns. The - prefix remains available in DMs.

Current operation: J.A.R.V.I.S. is running with Discord's privileged Members, Message Content, and Presences intents disabled. Mention commands, interactions, message metadata, and individual account lookups support the recovered features below. These alternatives do not provide a complete member-event stream or ordinary-message text access.

Moderation and server safety

  • Configured message deletion and cleanup, including timed removal in selected channels.
  • Warnings, mutes, and moderation records for staff review.
  • Deletion-event logging in the private #server-logs channel. Deleted message text may be unavailable; edited messages are not currently being logged.
  • HTML transcripts of scheduled cleanup posted in #server-logs, using message content and metadata available to the bot. These records are accessible only to moderators and administrators.

Message filtering in the official server is handled by Discord's AutoMod rules.

Member and role management

  • Welcome DMs triggered by available native Discord join notices in the official server. A missing notice means the welcome DM may not be sent, including on a rejoin.
  • Restoration of configured sticky roles from verified records, including selected moderation restrictions and any notification roles specifically marked sticky. Role-change audit information tracks additions and removals. A paced watch checks selected recorded members for a changed join time, allowing restoration without a native join notice.
  • Reaction roles and self-assignable roles through configured dropdown menus.
  • A periodically refreshed approximate total-member counter.

Sticky-role restoration is not immediate. A small watch list normally takes about one to two minutes; larger lists, missing permissions, role hierarchy, and Discord API delays can increase the wait or prevent restoration. Existing holdings need a verified baseline; old saved records are not blindly reapplied. Full automatic join/leave logging and role-change notifications are currently unavailable.

Message and channel automation

  • A cooperative counting channel using /count to submit the next number. Accepted counts are posted publicly with the member's attribution; incorrect or consecutive attempts receive a private interaction response. Configured goal and progress announcements remain public.
  • Ordinary user posts in the counting channel are removed while Message Content access is unavailable. The bot may DM an instructional reminder, limited to one per member per server every ten minutes. Contribution records are retained, but this community does not display a counting leaderboard.
  • Automatic reactions in designated channels.
  • Message voting, announcement publishing, and slowmode controls.
  • Scheduled commands, including automatic weekly XP leaderboard posts in the configured channel.

Community features and notifications

  • Member leveling from eligible message activity, subject to configured cooldowns, channel restrictions, and role restrictions. The current activity mode does not compare ordinary message text for repetition, similarity, or minimum length.
  • Lifetime, current-week, and previous-week leaderboards from recorded participant statistics. Display names are resolved through available account information and paced lookups; an unavailable name retains a user-ID fallback.
  • Configured clearance-role and weekly-reward functionality. Weekly award processing verifies current membership separately from the displayed participant scores.
  • Voice participation statistics; voice XP is currently disabled.
  • Button-entry giveaways with entrant names and entry counts, preserved custom-host attribution, and selected-winner lookups. Entrant names load as pages are viewed; unavailable names retain their IDs. A failed winner lookup retains the selected winner for staff review instead of silently redrawing.
  • RSS, Reddit, and YouTube notifications.

Leaderboard entries reflect saved participant records, which can include members who have left. Displaying a name or score does not establish current server membership.

Administration

Administrators use permissions controls, scheduled commands, aliases, and other bot management utilities to configure server behavior. Server commands use the same mention-based access described above.

Discord data needed for these features

Member and role information is obtained for selected accounts when needed for interactions, giveaway winner checks, rewards, or sticky-role restoration. Role-restoration records use role-change audit information and observed join timestamps. The approximate member counter uses Discord's aggregate count rather than a complete member roster.

Message and interaction data supports mention commands, DMs, slash-command parameters, reactions, and buttons. The bot can also receive ordinary-message metadata without access to its text. Text-based XP checks and ordinary-message counting validation are not active in the current reduced-access modes. Moderation records and transcripts can preserve only content actually available to the bot.

The online counter and presence-based leveling bonuses are not configured.

Processing data for a feature and retaining it are different. See the privacy policy for the data retained by leveling, counting, role restoration, moderation, and other configured functionality.
