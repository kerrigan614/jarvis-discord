What the bot does

Core features

J.A.R.V.I.S. supports the day-to-day operation of two MARVEL Strike Force Discord communities. Availability and behavior depend on each server's configuration and channel permissions.

Commands and interactions

Use the - prefix in server channels or DMs, such as -help or -weekly. Server commands also accept an actual bot mention followed by the command, such as @J.A.R.V.I.S. help. Counting accepts ordinary numbers or the optional /count command; giveaway entries and role selections use their configured buttons, reactions, and dropdowns.

Current operation: Members and Message Content intents were restored and enabled on November 25, 2026. The bot can again receive member events and ordinary message content in channels it can access. Presence intent remains disabled. Recovery fallbacks remain available if access is lost; they do not replace the normal member and message handling while these intents are enabled.

Moderation and server safety

  • Configured message deletion and cleanup, including timed removal in selected channels.
  • Warnings, mutes, and moderation records for staff review, with moderator-name lookups when a saved account is missing from the cache.
  • Configured member join, leave, and role-change logs, plus message edit and deletion logs, in the private #server-logs channel. Message logs depend on what the bot received and cached; content from uncached messages or messages received without text access may be unavailable.
  • HTML transcripts of scheduled cleanup posted in #server-logs, using message content and metadata available to the bot. These records are accessible only to moderators and administrators.

Message filtering in the official server is handled by Discord's AutoMod rules.

Member and role management

  • Welcome DMs triggered by member-join events in the official server, subject to configured screening and welcome settings. They no longer depend on Discord posting a native join notice. Delivery also depends on the member's DM settings.
  • Restoration of configured sticky roles when members rejoin, including selected moderation restrictions and notification roles specifically marked sticky. Member role updates track the saved roles.
  • Reaction roles and self-assignable roles through configured dropdown menus.
  • A total-member counter using normal server member information and join/leave updates, with queued channel edits to respect rate limits.

Sticky-role restoration uses native join events rather than the recovery polling interval. Missing permissions, role hierarchy, and Discord API failures can delay or prevent restoration. The separate RoleNotify extension remains unloaded.

Message and channel automation

  • A cooperative counting channel accepting ordinary numbers. Correct entries remain in the channel and receive the configured reaction. Invalid or consecutive entries are handled by the channel's configured counting rules.
  • The optional /count command shares the same sequence and turn rules. Accepted slash-command counts are posted publicly with member attribution; rejected slash attempts receive a private interaction response. Configured goal and progress announcements remain public. Resetting the count also clears the previous member's turn restriction.
  • Contribution records are retained, but this community does not display a counting leaderboard. Recovery-only instructional DMs are inactive while Message Content access is enabled.
  • Automatic reactions in designated channels.
  • Message voting, announcement publishing, and slowmode controls.
  • Scheduled commands, including automatic weekly XP leaderboard posts in the configured channel.

Community features and notifications

  • Member leveling from eligible messages, subject to configured text-length and repetition/similarity checks, cooldowns, channel restrictions, and role restrictions. The metadata-only activity XP fallback is inactive while Message Content access is enabled.
  • Lifetime, current-week, and previous-week leaderboards from saved statistics. Current server leaderboards use member-cache filtering; saved previous-week results reflect that period. Display names use available account information and paced lookups when needed.
  • Configured clearance-role and weekly-reward functionality. Weekly award processing verifies current membership before assigning rewards.
  • Voice participation statistics; voice XP is currently disabled.
  • Button-entry giveaways with entrant names and entry counts, preserved custom-host attribution, and selected-winner lookups. Entrant names load as pages are viewed; unavailable names retain their IDs. A failed winner lookup retains the selected winner for staff review instead of silently redrawing.
  • RSS, Reddit, and YouTube notifications.

A displayed name or saved result does not establish current membership. Unavailable names retain a user-ID fallback.

Administration

Administrators use permissions controls, scheduled commands, aliases, and other bot management utilities to configure server behavior. Prefix and mention commands remain subject to the same permission checks.

Discord data needed for these features

Member and role information supports join/leave handling, configured member-change logs, welcome DMs, sticky-role restoration, member counts, interactions, and reward or giveaway checks. Member information is cached by the bot; individual lookups remain available when needed.

Message and interaction data supports prefix and mention commands, ordinary-number counting, content-based XP checks, configured message logs and cleanup transcripts, DMs, slash-command parameters, reactions, and buttons. Moderation records and transcripts preserve only content actually available to the bot.

Presence access remains disabled. The online counter and presence-based leveling bonuses are not configured.

Processing data for a feature and retaining it are different. See the privacy policy for the data retained by leveling, counting, role restoration, moderation, and other configured functionality.
