How Discord data is handled

Privacy policy

Effective and last updated: October 7, 2026

1. Scope and operator

This policy applies to J.A.R.V.I.S., a private, self-hosted Discord bot maintained by its individual operator. It operates in the official MARVEL Strike Force Discord server and the operator's private MARVEL Strike Force alliance server. It is not publicly installable.

J.A.R.V.I.S. uses Red-DiscordBot and selected community extensions to provide configured server functionality. This policy describes that bot instance. Discord and external services have their own privacy policies.

2. Data accessed and collected

The bot processes data made available through Discord only as needed for its configured features and within its permissions. Depending on the feature, this can include:

  • Identifiers and member information: Discord user, server, channel, message, and role IDs; usernames, display names, nicknames, membership changes, roles, and permissions.
  • Messages and reactions: message content and associated metadata, including embeds or attachment information where relevant to configured moderation, reports, commands, or channel automation; reactions used for voting and karma.
  • Voice participation: voice-channel state and participation duration used for configured leveling. This does not involve recording voice audio.
  • Feature and moderation records: leveling statistics, karma totals, role-restoration state, warnings, mutes, moderation actions, submitted reports, and related configuration or diagnostic records.

3. How data is used

Data is used to provide moderation, member and role management, message and channel automation, leveling, notifications, and administrative functionality. For example, the bot reads a counting-channel message to evaluate the next number and receives member join events to perform configured welcome and role behavior.

J.A.R.V.I.S. is not monetized. Discord data is not sold, used for advertising or marketing profiles, or used to train machine learning or artificial intelligence models.

4. Data stored outside Discord

Limited Discord-derived data is stored locally on the system running the bot when persistence is needed. Established examples include:

  • LevelUp: Discord IDs, message counts, and time spent in voice channels.
  • ReactChannel: Discord IDs and karma totals based on message upvotes and downvotes.
  • RoleTools: user IDs and configured role information used to restore roles when a member rejoins. User IDs may also appear in bot logs.
  • Red core and moderation functionality: a limited username or nickname history, account-linked actions, moderation records, and content deliberately supplied to features such as member reports.

The installed Counting extension reports that it does not persistently store data about users. Other features may maintain configuration or records necessary for their operation.

J.A.R.V.I.S. does not maintain a general archive of ordinary server conversations. Processing a message for filtering, counting, or reactions does not itself mean the message is retained as conversation history. Specific message content may appear in submitted reports or configured moderation logs, including logs posted within Discord.

5. Access and sharing

The operator administers the bot's local data. Authorized server administrators or moderators may see reports, moderation records, and other feature outputs according to server permissions. Community features such as leaderboards, karma, or role notifications may display relevant results to members in configured channels.

Data is transmitted to Discord as needed to provide bot responses and server functionality. External feed and notification features retrieve content from their respective services; they are not used to export ordinary Discord conversations.

Discord API data is not otherwise shared with third parties except with service providers necessary to operate the bot, when expressly directed by the user, or as required by applicable law, consistent with Discord's terms.

6. Retention

Stored data is retained only while necessary for the feature that uses it. Retention depends on the record and configured functionality; the bot does not apply one fixed retention period to every category. For example, role-restoration data may remain after a member leaves so that configured roles can be restored if they return.

Data will be promptly deleted when no longer needed, when the bot stops operating, or following a deletion request from the applicable user or Discord, except where applicable law requires retention. Automated deletion tools may not remove every record; the operator handles remaining records through the manual request process below.

7. Privacy requests and deletion

For questions, correction requests, or deletion requests, contact the operator through Discord. You can send J.A.R.V.I.S. a direct message using -contact followed by your request. If that command is unavailable or you cannot reach the bot, contact an administrator of a server where it operates privately and ask to be connected with the J.A.R.V.I.S. operator.

Include your Discord user ID and the server or feature involved so the operator can locate the relevant records. Requests may require verification that you control the account. Do not post private information in public channels or GitHub issues.

Red also provides these commands using J.A.R.V.I.S.'s - prefix:

  • -mydata whatdata explains Red's data practices.
  • -mydata 3rdparty provides data statements from loaded community extensions.
  • -mydata forgetme initiates deletion of data supported by Red and participating extensions. Follow the bot's confirmation instructions.

-mydata forgetme may leave operational or moderation records and data from extensions that do not implement deletion. Contact the operator to request review and deletion of remaining data. These command limitations do not replace the manual deletion process.

There is no individual opt-out from message processing necessary for configured moderation and channel automation while participating in affected channels. Deletion removes stored data; later interactions may generate new records needed for the applicable feature.

8. Documentation website and policy updates

This documentation website contains no added analytics, advertising scripts, or tracking cookies. GitHub Pages hosts the site and may process visitor information under GitHub's privacy statement. The public documentation repository contains documentation, not the bot's stored user data.

This policy will be updated when the bot's data practices change. The current version and update date will remain available on this page.
